The **RestExceptions.FluentValidation** package maps [FluentValidation](https://docs.fluentvalidation.net)'s `ValidationException` to a REST error response.

> Available since 10.1.0. Requires FluentValidation 11.0.0 or later.

### 1. Installation

```bash
dotnet add package RestExceptions.FluentValidation
```

> For more information, visit [nuget.org/RestExceptions.FluentValidation](https://www.nuget.org/packages/RestExceptions.FluentValidation).

### 2. Registration

```csharp
builder.Services.AddRestExceptions(options => options.AddFluentValidation());
```

> Without `AddFluentValidation()`, a `ValidationException` results in a 500 Internal Server Error.

### 3. Choosing the status code

The status code comes from each rule's `ErrorCode`. All of the following result in 409 Conflict:

```csharp
public class CreateUserRequestValidator : AbstractValidator<CreateUserRequest>
{
    public CreateUserRequestValidator()
    {
        RuleFor(x => x.Name)
            .Must(BeUnique)
            .WithErrorCode("409");                              // the numeric code
            // or .WithErrorCode("Conflict")                    // the RestException name, without its suffix
            // or .WithErrorCode(nameof(ConflictRestException)) // the RestException type name
            // or .WithErrorCode(nameof(HttpStatusCode.Conflict)) // the HttpStatusCode member name
    }
}
```

> Matching is case-insensitive.

Then, validate and throw:

```csharp
new CreateUserRequestValidator().ValidateAndThrow(request);
```

#### Rules

- An error code that does not resolve to a status code, such as FluentValidation's default `"NotEmptyValidator"`, counts as **400** Bad Request.
- Only failures with `Severity.Error` decide the status code, unless there are none.
- If the failures disagree on the status code, the result is **400** Bad Request.

### 4. Response

The failures are added to the `errors` extension, grouped by property name.

With a single failure, its message becomes the `detail`:

```json
{
  "type": "https://www.rfc-editor.org/rfc/rfc9110.html#name-409-conflict",
  "title": "Conflict",
  "status": 409,
  "detail": "A user named 'taken' already exists.",
  "instance": "/users",
  "originalException": "ValidationException",
  "errors": {
    "Name": [ "A user named 'taken' already exists." ]
  },
  "traceId": "00-f3e52009f0966d717f93c9653ed45e26-750dad4218610f7f-00",
  "method": "POST",
  "requestId": "0HNE94J42PNH8:00000001"
}
```

With multiple failures, the `detail` is `"One or more validation errors occurred."`:

```json
{
  "type": "https://www.rfc-editor.org/rfc/rfc9110.html#name-400-bad-request",
  "title": "Bad Request",
  "status": 400,
  "detail": "One or more validation errors occurred.",
  "instance": "/users",
  "originalException": "ValidationException",
  "errors": {
    "Name": [ "A user named 'taken' already exists." ],
    "Email": [ "Emails from 'blocked.example' are not allowed." ]
  },
  "traceId": "00-f3e52009f0966d717f93c9653ed45e26-750dad4218610f7f-00",
  "method": "POST",
  "requestId": "0HNE94J42PNH8:00000001"
}
```

> The keys are available as constants: `ValidationExceptionMapper.ErrorsExtensionKey` and `ValidationExceptionMapper.MultipleFailuresMessage`.
