Map any exception type, including your own or a third-party library's, to a `RestException`.

> Available since 10.1.0.

### 1. Create the mapper

Implement [IRestExceptionMapper](https://github.com/stratisd-labs/rest-exceptions-dotnet/wiki/5.-API-reference#irestexceptionmapper). Return `null` for the exceptions the mapper does not handle.

```csharp
public sealed class TimeoutMapper : IRestExceptionMapper
{
    public RestException? Map(Exception exception)
    {
        return exception is TimeoutException
            ? new GatewayTimeoutRestException(exception.Message)
            : null;
    }
}
```

When the status code is only known at runtime, use [RestExceptionFactory](https://github.com/stratisd-labs/rest-exceptions-dotnet/wiki/5.-API-reference#restexceptionfactory):

```csharp
public sealed class HttpRequestMapper : IRestExceptionMapper
{
    public RestException? Map(Exception exception)
    {
        return exception is HttpRequestException { StatusCode: { } statusCode }
            ? RestExceptionFactory.Create(statusCode, exception.Message)
            : null;
    }
}
```

### 2. Register the mapper

```csharp
builder.Services.AddRestExceptions(options => options
    .AddMapper<TimeoutMapper>()
    .AddMapper<HttpRequestMapper>());
```

### 3. How mappers run

1. A thrown `RestException` is used as is. It is never passed to a mapper.
2. Otherwise, the mappers run in registration order. The first one that returns a result wins.
3. If no mapper returns a result, the [built-in exception mapping](https://github.com/stratisd-labs/rest-exceptions-dotnet/wiki/6.-Built-in-exception-mapping) is used.

So, a mapper can also change the built-in mapping. E.g. to return 409 Conflict for `InvalidOperationException`:

```csharp
public sealed class InvalidOperationMapper : IRestExceptionMapper
{
    public RestException? Map(Exception exception)
    {
        return exception is InvalidOperationException
            ? new ConflictRestException(exception.Message)
            : null;
    }
}
```

### Notes to remember

- Mappers are registered as **singletons**, so they cannot depend on scoped services.
- Registering the same mapper type more than once has no effect.
