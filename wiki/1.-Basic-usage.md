### 1. Installation

```bash
dotnet add package RestExceptions
```

...or by using the NuGet Package Manager.

> For more information, visit [nuget.org/RestExceptions](https://www.nuget.org/packages/RestExceptions).

### 2. Adding the middleware

```csharp
// Program.cs

var builder = WebApplication.CreateBuilder(args);

// ...

// Add the service
builder.Services.AddRestExceptions();

var app = builder.Build();

//! Important
app.UseExceptionHandler();

// ...

app.Run();
```

### 3. Usage

```csharp
throw new NotFoundRestException();
```

Exceptions that are not a `RestException` are handled too. See [Built-in exception mapping](https://github.com/stratisd-labs/rest-exceptions-dotnet/wiki/6.-Built-in-exception-mapping).

### 4. Result

The result is a standardized REST error response:

```json
{
  "type": "https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.5",
  "title": "Not Found",
  "status": 404,
  "detail": "Content not found.",
  "instance": "/users/12",
  "traceId": "00-f3e52009f0966d717f93c9653ed45e26-750dad4218610f7f-00",
  "method": "GET",
  "requestId": "0HNE94J42PNH8:00000001"
}
```

### 5. Logging

Since .NET 10, ASP.NET Core no longer logs exceptions that an `IExceptionHandler` handles.
RestExceptions therefore logs every exception that results in a **5xx** response as an error, using the `RestExceptions.RestExceptionHandler` log category.

**4xx** responses are not logged, as they are expected outcomes rather than failures.
